# QA·Security 실행

1. `qa-policy.md`를 읽고 그 파일의 판정과 기록 규칙을 따른다.
2. 변경 파일과 영향 범위를 확인한다. 기존 TC로 커버되면 TC를 늘리지 않는다. 요구사항이 불명확하면 추측하지 않고 RISK로 남긴다.
3. 제품 코드를 고친 뒤, 완료라고 말하기 전에 저장소 루트에서 `python3 qa/run.py`를 실행한다.
4. 종료 코드가 0이 아니면 `qa/reports/`에 생긴 이번 RUN의 `fail.md`와 `risk.md`를 사용자에게 보고한다. HIGH 또는 CRITICAL이 OPEN이면 완료·병합으로 처리하지 않는다.
5. 결함을 수정하기 전에 해당 FAIL과 RISK가 이미 MD에 있는지 확인한다. 없으면 먼저 기록한다.
6. 수정 후에는 같은 명령으로 두 도구 재검증과 회귀가 다시 실행됐는지 확인한다.
